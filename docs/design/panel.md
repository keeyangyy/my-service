# 面板与服务设置

> 状态：**已实现（后端）**（2026-11-14 重构）

## 分组

面板按 `mode` 分三块：

| 区块 | mode | 说明 |
|:--|:--|:--|
| 常驻服务 | `managed` | 起来就一直跑 |
| 即用即走 | `on_demand` | 点开才起、超时回收 |
| 定时任务 | `task` | 到点跑一次 |

空组隐藏。各组独立拖拽排序，**跨组拖不动**（分组由 `mode` 决定）。`runtime.order` 是全局序号，面板按 `(mode, order)` 排序。

## 状态展示（六态）

| 状态 | 徽标 | 说明 |
|:--|:--|:--|
| `running` | 绿 | 健康通过 |
| `starting` / `stopping` | 黄 | 过渡态 |
| `failed` | 红 | 启动失败 / 崩溃 |
| `stopped` | 灰 | 未运行；端口被占、身份不符也归此态，原因写在 `error` |
| `invalid` | 红 | 注册条无效 |

错误文本直接展示在行内：

```
端口 33510 被 chrome.exe 占用（不是本服务）
健康目标自报 service=xxx，非本服务
```

置信度与来源放在悬浮提示 / 设置面板：

```
置信度：confirmed / probable / unknown
PID 来源：handle / framework-pidfile / service-pidfile / port / process
运行起点：进程创建时间 / 框架拉起 / 接管 / 首次观测
```

## 按钮可用性

| 条件 | 启动 | 停止 | 回收 |
|:--|:--|:--|:--|
| 有 `start` | ✅ | — | — |
| 有 `pid`（任意来源） | — | ✅ | ✅ |
| `pid = null` 且 `confidence=unknown` | — | 置灰 | 置灰 |
| `pid` 来自进程名且匹配多个 | — | 置灰（防误杀） | 置灰 |

## 设置面板（每行 ⚙）

| mode | 可改项 |
|:--|:--|
| `managed` | 自启 |
| `on_demand` | 超时回收时长（`idle_timeout_sec`）、自启（默认关） |
| `task` | 启用、补跑、执行超时、调度时刻（单独区块） |

`自启` 开关留在主行；`enabled: false` 时自启一并失效。

## 编排器全局设置（header ⚙）

| 项 | 默认 | 说明 |
|:--|:--|:--|
| 面板刷新（可见） | 1 秒 | 浏览器轮询 |
| 面板刷新（隐藏） | 10 秒 | 标签页不可见时 |
| monitor 活跃间隔 | 1 秒 | 收到 `/api/panel/ping` |
| monitor 空闲间隔 | 10 秒 | 无面板心跳超过宽限期 |
| scheduler 间隔 | 10 秒 | 定时任务检查频率 |
| 事件保留天数 | 7 天 | `audit_retention_days`，0 = 永不清理 |
| 备份保留份数 | 7 份 | `backup.keep`，0 = 不自动清理；保存后立即收敛一次 |
| 备份 | — | 立即备份 `reg/` + `config.json` + `adapters/` 到 `data/bak/`（不进 git） |

写入 `config.json`，重启后仍生效。

## Dashboard 布局

- 服务行：状态灯 / 启停 / ↗ / 事件窗 / 自启 / `⚙ 设置`，行首 `⠿` 拖拽；
- 定时任务区：下次执行 / 上次结果 / 事件窗 / ▶ 立即运行 / `⚙ 设置`；
- header：宿主运行时长 + 版本 + `▤ 登记簿` + 全局 `⚙ 设置` + 重启/停止宿主。

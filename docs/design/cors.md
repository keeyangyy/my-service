# 控制面跨源策略（CORS）

> 状态：Accepted ｜ 实现：`src/core/api/cors.py`（判定）、`src/core/api/__init__.py`（路由门禁）

## 前提

控制面绑定 `127.0.0.1:1236`，**本机任何程序（curl / 脚本 / 其他服务）本来就能直接调用**，从来不需要额外开放。唯一受限的是"浏览器里的网页"：跨源时浏览器默认不把响应交给页面 JS，带 JSON 的请求还会先发 `OPTIONS` 预检、没被应答就根本不发。

**判据只有一条：来源是否本机**（端口不限）。

| 谁来 | 判定 | 结果 |
|:--|:--|:--|
| 面板自己（同源，无 `Origin`） | 本机 | 全放行，**行为与历史完全一致** |
| 本机任意网页（`localhost` / `127.0.0.1` / `::1`，**任意端口**） | 本机 | 全放行 + 回 `Access-Control-Allow-Origin`，**能读到返回** |
| 本机程序（curl / 脚本，不带 `Origin`） | 本机 | 全放行（现状） |
| 外站网页 | 非本机 | 预检 `403`、写接口 `403`，且响应不带任何 CORS 头 |

## 为什么必须留外站这道闸门

CORS 只管"能不能读回"，**不管"能不能发出"**。若不拦，任意网页用一段自动提交的 `<form action="http://127.0.0.1:1236/api/host/stop">` 就能停掉宿主——它读不到返回也无所谓，动作已生效。

浏览器跨源 POST **必定带 `Origin`**，故外站可被可靠识别；不带 `Origin` 的（curl / 脚本）按本机程序处理。

## 被拦的写接口

`/api/services/*`、`/api/crons/*`、`/api/audit/clear`、`/api/config/*`、`/api/host/*`。

读接口不拦（外站拿不到 CORS 头，浏览器自会扣下响应）。

## 逃生开关

`config.json`：`"cors_local_only": true`（默认）。置 `false` 即整体退回"不回 CORS 头、不答预检"的历史语义，应急时不必回滚代码。

## 典型用法

按需服务被空闲回收后，它的页面自己就是"死掉的那个进程"，救不了自己；此时由页面调宿主的 `POST /api/services/{自己}/start` 原地复活，再轮询自己的 `/health` 判断活过来没有——全程不跳转、不离开页面。

## 已知边界（不是 bug）

`file://` 直接双击打开的页面，其 `Origin` 是字符串 `null`，按外站处理。目前无此用例，保持拒绝。

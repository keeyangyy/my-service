# 定时任务（reg/tasks/*.json）

> 状态：Accepted ｜ 实现：`src/core/scheduler.py`

## 第二物种：到点跑一次脚本

不是所有"服务"都需要常驻：签到、备份、清理、定期拉取……这类一次性脚本用 `reg/tasks/<任务名>.json` 注册，由宿主内置调度线程到点执行，**无常驻进程、无健康检查、无状态机**。

`reg` 的扫描不递归，`cron/` 子目录与服务注册天然隔离，不会混进服务列表。

## 注册条协议

```jsonc
{
  // ★ 只放声明：enabled / timeout_sec / catch_up 属运行态（存 data/cron_runtime.json）；
  //   schedule 是"账本缺失时的默认计划"——面板改的时刻只进账本，不写这里
  "path": "C:/path/to/your-service",      // ★ 脚本所在真实家（与服务注册条同语义）
  "enabled": true,                          // 运行态：false = 暂停调度（面板显示已停用）
  "display": "示例：每日签到",
  "description": "示例：每日签到",
  "entry": "run_all.py",                    // 相对 path；支持 .py/.ps1/.cmd/.bat/.exe
  "args": ["--site", "example"],
  "cwd": ".",
  "schedule": {"type": "daily", "at": ["09:30", "14:30"]}, // daily：每日可多个时刻（数组；旧字符串自动兼容）
  // 或 {"type": "interval", "every_sec": 3600}
  "timeout_sec": 300,                       // 挂死保护（默认 300，下限 5s），超时 taskkill /T 树杀记失败
  "catch_up": false,                        // 错过是否补跑（默认 false）
  "env": {}                                 // 附加环境变量
}
```

## 调度语义（实弹验证过的边界行为）

- **daily**：每天本地时刻 `HH:MM` 触发；**interval**：固定间隔循环，新任务从被调度器见到起算一个周期后首跑（宿主频繁重启不会引发齐跑）。
- **防重叠**：上一轮没跑完，本轮到点不触发；跑完后 next_run 若已过期走统一的"错过"处理，绝不堆积连发。
- **错过**（宿主关闭/睡眠/执行超长导致，宽限阈 60 秒）：`catch_up: true` 立即补跑一次（签到类建议开）；默认 `false` 只登记 `cron_skip` 并顺延到下一合法时刻，开机绝不齐跑。
- **开关**：面板滑块（同服务自启滑块）控制是否参与调度，权威值只写运行态账本（`data/cron_runtime.json`）；只影响下一次触发，正在跑的一轮自然跑完；停用期间不排新计划，重新启用即恢复。
- **状态恢复**：`last_run/last_ok/last_rc/next_run` 持久化在 `data/cron_state.json`（scheduler 独写，运行期以内存为准），宿主重启后照单恢复。
- **触发记录**：卡片「事件」窗展开该任务的 `cron_run/cron_skip` 时间线（登记簿按任务名过滤）；note 只记结果与非常规来源（定时触发无前缀，手动触发/错过补跑以中文前缀区分），脚本自身输出仍由任务自己记录。
- **手动触发**：面板「▶ 立即运行」按钮 / `svc.ps1 cron-run <名>` / `POST /api/crons/{名}/run`；运行中重复触发返回 409 拒绝。

## 面板行内编辑

任务行默认**一行**，按钮与服务卡片同序（概览 + `启用` 开关 + `▶ 立即运行` + `⚙ 设置` + `事件`）；点 `⚙ 设置` 展开配置面板，内部分**两个带标题的分区**：

- **执行时机**：模式分段按钮二选一（定时执行 / 间隔执行）+ 时刻选择器或间隔数值 + 单位。
- **异常保护**：`⏲ 超时保护`秒数（卡死强杀阈值）、`补跑`开关。

并附一行说明点明"两者都不改变执行频率"。

- 为什么分区：超时保护与"多久跑一次"是两个维度，平铺摆放曾被误读成第三种调度方式。
- 改调度时间会**立即重算下次执行时刻**（否则面板显示新时间、实际仍按旧时间触发）。
- 写账本前用注册条规则重解析校验，不合法则**拒绝并回滚**，绝不留坏配置。
- 模式切换保留两种模式各自的最后已知值（本会话内），误点不会把原时间冲掉。
- 展开态跨轮询保持；正在输入的框不被轮询打断。
- 坏注册条（invalid）的配置面板控件与 `⚙ 设置` 按钮一律禁用（面板改不了根因）。

## 拖拽排序

服务列表与定时任务列表都支持：行首把手 `⠿`，按住上下拖动，松手自动保存（服务存 `data/service_order.json`、任务存 `data/cron_order.json`，均为框架侧记账，不污染注册条）。

新注册的服务/任务自动排在末尾；注销条目的顺序自动清理；重启宿主后顺序保持。想恢复默认字母序：把行拖回字母序即可（只删账本文件不会重置内存里的顺序，需配合重启宿主）。

## 日志边界

与服务同一条铁律：脚本输出一律 DEVNULL 不接管——任务日志由任务自己写（一次性脚本建议自行追加写自己的日志文件）；框架只把"何时触发了、成没成、耗时、退出码"记进登记簿（`cron_run`/`cron_skip`）。

## 注册 / 注销

在 `reg/tasks/` 放/删 `<任务名>.json` 即可，无需重启宿主；无效注册条在面板标 invalid 并附原因（缺 schedule、入口不存在等）。
